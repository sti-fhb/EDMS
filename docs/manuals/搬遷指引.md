# 把這套流程搬到其他專案

本流程（`/sti-manual` 指令＋四支工具＋三份規範）不綁 TBMS，換專案可整套複製。
**專案專屬的設定集中在 `tools/manual_config.py`**，其餘檔案原樣照搬即可。

---

## 一、要複製哪些檔案

```
.claude/commands/sti-manual.md         指令定義
docs/manuals/
  tools/manual_config.py               ← 專案專屬設定，唯一要改的程式
  tools/gen_manual.py                  手冊產生器
  tools/gen_acceptance_form.py         測試報告產生器
  tools/check_manual.py                單檔格式檢查
  tools/check_consistency.py           跨檔一致性檢查
  tools/樣式範本.docx                  ← Word 版面來源，見第三節
  README.md                            流程總覽
  手冊撰寫規範.md                      ← 對照表與用語需改，見第四節
  截圖作業指引.md                      拍圖規範
  搬遷指引.md                          本檔
```

目錄結構（`et/`、`_images/`、`_tests/`、`_shots/`、`測試報告/`）由指令首次執行時自建，
不必預先建立。

---

## 二、改 `manual_config.py`

四支工具一律自此讀取，**改這一個檔就好**。四段設定：

| 段 | 改什麼 | 沒改的後果 |
|---|---|---|
| 一、機關與文件 | 機關名、購案名、文件名、撰寫人 | 封面印成別的專案 |
| 二、模組 | `MODULE_NAMES`（封面用之正式名稱）、`MODULE_DIRS`（模組資料夾） | 模組名印錯；未列於 `MODULE_DIRS` 之資料夾其手冊被默默跳過 |
| 三、命名慣例 | `MANUAL_NAME_RE`、`OPERATION_CODE_RE` | 新專案之作業編碼若非「兩碼英文＋兩位數字」，全部手冊會被當成他人文件略過 |
| 四、禁用字樣 | `MSG_CODE_RE`（訊息代碼格式） | 內部識別漏檢，會跟著送到客戶手上 |

> 重要：`MODULE_NAMES` 之名稱 **MUST 取客戶交付文件所用之正式名稱**，⛔ 不得以
> 內部慣稱替代（如 spec 與程式稱「ET 模組」，院方文件則為「教育訓練文件管理模組」）。
> 該名稱印在封面，錯誤即交付瑕疵；未確認前寧可不列——未列者封面只印作業名。

`TABLE_NAME_RE` 自 `MODULE_DIRS` 組成，新增模組時毋須另改。

## 三、樣式範本

`tools/樣式範本.docx` 是 Word 版面的**唯一來源**——字體、頁碼、分節、編號定義全部
繼承自它。刪掉就產不出文件。

### 同一個客戶、格式要求相同

範本直接沿用，不必處理。

### 不同客戶或格式不同

要重做一份：

1. 取一份**客戶已認可格式的定稿文件**（如需求規格確認書）
2. 清空其 body，但保留 `styles.xml`、`numbering.xml` 與分節設定
   （分節符寄生在某個段落的 `pPr` 內，**刪掉該段落會連帶失去頁碼配置**）
3. 移除未被引用的圖片 part——原文件的插圖仍留在 package 裡，不清會讓範本肥大
   （TBMS 這份從 8.4MB 壓到 25KB）

⛔ **不可拿產出的手冊充當範本**：產手冊時需同時讀寫同一檔（Word 開著即失敗），
且樣式會逐代退化。

## 四、改 `手冊撰寫規範.md`

程式讀不到、但同樣專案專屬的部分：

- **作業名稱對照表**（第七節）——代碼與正式名稱，一致性檢查會拿它核對手冊檔名
- **用語規範**（第七節）——模組名稱、角色名稱、訊息分類之權威口徑
- **禁止事項**（第八節）——內部角色代號、訊息與錯誤代碼格式，依新專案之實際情況調整
- **章節骨架**（第三節）——固定三章的結構通用，但各節內容視系統性質可調
- **個資規則**（第六節）——⚠️ 這是**規則不是範例**。它以「含某某資料者一律遮罩」的
  形式寫成，而那個「某某」是前一個專案的當事人類型；換專案後條件匹配不到任何東西、
  遮罩要求即形同失效，且不會有任何徵兆。必須改成新專案實際的個資欄位

## 四之二、`README.md` 與 `截圖作業指引.md` 也要改

⚠️ **本節原寫「這兩個檔不含專案專屬內容，原樣照搬」——那是錯的。** 2026-09-16 搬至
EDMS 時，這兩個檔各有 7 處舊案內容，而正是那句話讓它們被跳過、事後才逐一挖出來。

| 檔案 | 要改什麼 |
|---|---|
| `README.md` | 通篇以某一支作業當範例貫穿（流程圖、md 路徑、骨架、圖說、指令列、兩則「重要」提醒），以及按鈕字樣舉例 |
| `截圖作業指引.md` | **登入身分**（⚠️ 規則：舊案為站點別，新案多為角色別）、**個資規則**（同第六節）、資料準備的具體資料範例、操作方式範例 |

**登入身分與個資那兩處是規則，不是範例** ——照舊值留著，拍圖的人會不知道該用什麼帳號
登入，遮罩要求也會失效。

> 建議搬遷時逐檔 grep 舊專案的作業碼前綴與領域詞彙，**大小寫都要搜**——作業碼的小寫
> 形式會出現在指令範例（`/sti-manual xx01`）與圖檔路徑（`_images/xx/xx01-01.png`）裡，
> 只搜大寫會漏掉一半。此外「N 支作業」這類數量、以及按鈕字樣的舉例都不含作業碼，
> 純 grep 代碼抓不到，要順著目視一遍。

## 五、指令要改的地方

`.claude/commands/sti-manual.md` 的**步驟 1 與步驟 2**寫死了規格文件的位置與對照方式：

- 規格路徑 `docs/specs/{模組}/spec_us{N}.md`
- 作業碼與 US 編號不一致，須查 `spec.md` 的對照表

新專案若規格文件的組織方式不同，這兩步要照著改。其餘步驟（盤點現況、詢問範圍、
撰寫、檢查、開待拍清單、產出）與專案無關。

---

## 六、搬完怎麼驗

依序跑，四支都要過：

```bash
python docs/manuals/tools/check_manual.py
python docs/manuals/tools/gen_manual.py docs/manuals
python docs/manuals/tools/gen_acceptance_form.py
python docs/manuals/tools/check_consistency.py
```

- [ ] 第一支手冊產得出來，且印出「內容核對通過」
- [ ] 開啟 Word：封面的機關名、購案名、模組名、作業名皆正確
- [ ] 目錄頁碼正確（首次開啟會自動更新）
- [ ] 頁首頁尾、字體、段落與客戶的定稿文件一致
- [ ] 測試報告的表格跨頁時標題列有重複

最後一項最容易漏——要翻到第二頁才看得出來。

> 重要：檢查工具驗不到**內容是否與系統一致**。搬遷驗的是版面與流程跑得通，
> 手冊寫得對不對仍須對截圖或實機核對。
