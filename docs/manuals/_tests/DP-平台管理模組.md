# 平台管理模組

## DP01 使用者管理

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者帳號（主要） | 具教育訓練或文件管理任一模組之管理者角色，本作業絕大多數項目以此帳號操作 |
| 管理者帳號（另一模組） | 另一個模組的管理者帳號，用於驗證帳號為兩模組共用、所見相同（第 1 項）；兩模組管理者為同一人時此項驗不到 |
| 可收信的 Email | 一個**尚未在系統中使用過**且測試當下收得到信的 Email，用於建立帳號與完成啟用（第 5～9 項）；收不到信則整段啟用流程驗不到 |
| 已存在之帳號 | 一個已完成啟用的帳號，用於驗證 Email 重複（第 10 項）與編輯姓名（第 23、24 項） |
| 已停用之帳號 | 一個狀態為「已停用」的帳號，用於驗證啟用（第 18 項）。可先以第 16 項停用一個帳號取得 |
| 鎖定中之帳號 | 以某帳號連續輸入錯誤密碼至被鎖定（失敗次數上限為系統參數，可於 DP03 系統參數與清單維護查得），用於驗證解鎖（第 21 項）。第 22 項需等鎖定期滿，鎖定時間為 DP03 的「帳號鎖定時間（分鐘）」，預設 30 分鐘 |
| 已逾期之邀請 | 一筆邀請狀態為「已逾期」者（第 15 項）。邀請效期即 DP03 的「密碼重設連結有效時間（分鐘）」，預設 30 分鐘，寄出邀請後等候逾時即可取得（調短此參數會一併影響忘記密碼連結，不建議） |
| 跨模組驗證用環境 | 受測使用者需在教育訓練或文件管理至少有一個可操作的頁面，用於驗證停用後即時失效（第 17 項） |
| 兩個瀏覽器或兩台裝置 | 第 17 項需一邊以管理者停用、另一邊以該使用者操作，確認是否立即被拒 |
| 因閒置被停用之帳號 | 第 19 項需一個由每日排程因閒置自動停用的帳號：測試前一日於 DP03 將「閒置停用天數（天）」暫調為 1，取一個已超過 1 天未登入的帳號，待次日每日排程（台灣時間 08:00）將其停用；測畢將參數調回原值（預設 90） |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 以教育訓練管理者與文件管理管理者分別進入本作業，兩者看到的帳號清單內容應相同。 |
| 2 | 於「關鍵字（姓名 / Email）」輸入姓名片段，清單應自動更新，不需另按查詢鈕。 |
| 3 | 於「帳號狀態」選「已停用」，清單應只列出狀態為已停用的帳號；併用關鍵字時兩項條件應同時成立。 |
| 4 | 切換至「待啟用邀請」頁籤，頁籤上的數字應等於該清單的實際筆數。 |
| 5 | 按「建立帳號」填入未使用過的 Email 與姓名，按「寄送邀請」並確認，該筆應出現在「待啟用邀請」頁籤。 |
| 6 | 承上，「帳號」頁籤**不應**出現該筆——使用者完成設定密碼前不建立帳號。 |
| 7 | 承上，收信並點連結、於效期內設定密碼後，該筆應自「待啟用邀請」消失並出現在「帳號」頁籤、狀態為啟用中。 |
| 8 | 承上，以該 Email 登入應可直接進入系統，不應再要求變更密碼。 |
| 9 | 承上，於 DP02 權限管理查看該使用者，應已具教育訓練的學員角色。 |
| 10 | 以**既有帳號**的 Email 建立帳號，應擋下並提示該 Email 已被使用，且不產生新的邀請。 |
| 11 | 以**已有待啟用邀請**的 Email 再建立一次，應擋下並提示改用重寄，且不產生第二筆邀請。 |
| 12 | 對一筆有效中的邀請按「重寄邀請」，應顯示已重寄；原連結應失效，新連結可正常設定密碼。 |
| 13 | 承上，立即再按一次「重寄邀請」，應被擋下並顯示尚需等待的分鐘數。 |
| 14 | 對一筆邀請按「取消邀請」並確認，該筆應自清單消失，且該 Email 可重新建立帳號。 |
| 15 | 邀請逾期後查看「待啟用邀請」，該筆邀請狀態應顯示「已逾期」，且其連結無法再設定密碼。 |
| 16 | 對一個啟用中的帳號按「停用」並確認，該列狀態應變為「已停用」，按鈕改為「啟用」。 |
| 17 | 承上，該使用者於教育訓練或文件管理的下一個操作應即被拒絕，不需等待其登出。 |
| 18 | 對已停用的帳號按「啟用」，狀態應恢復為「啟用中」，該使用者可再次登入。 |
| 19 | 對因閒置被排程停用之帳號按「啟用」但不登入，次日每日排程執行後，該帳號應再次變為已停用。 |
| 20 | 對目前登入中的本人帳號按「停用」，應被擋下並提示無法停用自己的帳號。 |
| 21 | 對鎖定中的帳號按「解鎖」，狀態應恢復為「啟用中」，該使用者可立即以正確密碼登入。 |
| 22 | 鎖定期滿後重新查詢該帳號，狀態應已自動恢復為「啟用中」，不需人工解鎖。 |
| 23 | 對某帳號按「編輯」，「帳號（Email）」欄位應為唯讀不可輸入，僅「姓名」可修改。 |
| 24 | 修改姓名後按「儲存」並確認，清單該列姓名應更新為新值，Email 不變。 |

## DP02 權限管理

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者帳號（兩模組） | 同時具教育訓練與文件管理管理者身分，本作業絕大多數項目以此帳號操作；兩個分頁都要看得到才測得到第 1 項 |
| 管理者帳號（單一模組） | 只具其中一個模組管理者身分者，用於驗證分頁只列出可管理的模組（第 1 項）；兩個帳號都是雙模組管理者時這項驗不到 |
| 受指派的一般使用者 | 一個啟用中、具學員角色、角色可自由增減的帳號，用於第 4、6、7、12、13 項。請勿使用測試者本人的帳號，否則會與第 5 項「不可取消本人角色」的檢核混淆 |
| 已停用之帳號 | 一個狀態為「已停用」且**已持有至少一個角色**的帳號（第 3 項要驗「已持有的角色同樣無法取消」，沒有既有角色就驗不到）。可於 DP01 使用者管理停用取得 |
| 可見對象選項 | DP03 系統參數與清單維護中，文件管理的「單位」與「職位」各至少 2 項且為啟用中 |
| 受訓對象選項 | DP03 系統參數與清單維護中，教育訓練的「單位」與「職位」各至少 2 項且為啟用中（與文件管理的清單各自獨立，需分別確認） |
| 掛配對之已發布課程 | 一門已發布、未關閉的課程，受訓對象只掛一組「單位甲 + 職位甲」（單位與職位皆不得為「全單位」「全體」）。受指派的一般使用者尚未加入該課程、受訓對象為「未指派」，且不得為該課程的建立者（第 12、13 項） |
| 可登入的受測帳號 | 第 7、13 項需以被指派者的身分登入確認，故需知道該帳號的密碼或可重設 |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 以僅具單一模組管理者身分的帳號進入本作業，應只看到該模組的分頁；具兩模組管理者身分者應看到兩個分頁。 |
| 2 | 於「關鍵字（姓名 / Email）」輸入後清單不應自動更新，按「查詢」或 Enter 後才套用篩選。 |
| 3 | 於文件管理分頁查詢已停用帳號，該列應標示「已停用」，其角色核取方塊與「編輯」皆不可操作——**連已持有的角色也不可取消**。 |
| 4 | 勾選某使用者的一個角色，畫面應顯示「角色 / 標籤已更新並即時生效」，且無須另按儲存；重新查詢後該勾選仍在。 |
| 5 | 對自己目前登入的帳號取消管理者角色，應被擋下並提示無法取消自己的管理者角色。 |
| 6 | 對同一使用者同時勾選兩個以上角色，應全部可並存（權限取聯集）。 |
| 7 | 為某使用者勾選文件管理的閱覽者後，以該帳號登入應可進入文件管理的功能，不需重新指派或等待。 |
| 8 | 於文件管理分頁按「編輯」，新增一組「單位 + 職位」並儲存，該列的可見對象欄應顯示該組配對。 |
| 9 | 新增一列只選「單位」未選「職位」即按「儲存」，視窗不應關閉，職位欄應標出紅框並提示補選或刪除；按該列的移除鈕後再儲存，可見對象欄不應出現該列。 |
| 10 | 移除一組既有的可見對象並儲存，該組應自欄位消失，其餘組別不受影響。 |
| 11 | 於教育訓練分頁按「編輯」，視窗應同樣以「單位」「職位」兩個下拉呈現；新增兩組配對並儲存，該列的受訓對象欄應同時顯示兩組。 |
| 12 | 為受指派的一般使用者新增「單位乙 + 職位甲」並儲存（職位相同、單位不同），該員**不應**出現在掛「單位甲 + 職位甲」之課程的學員清單中。 |
| 13 | 再為同一使用者新增「單位甲 + 職位甲」並儲存，該員應立即出現在該課程的學員清單中，並收到一封列出該課程的通知信。 |

## DP03 系統參數與清單維護

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者（兩模組） | 同時具教育訓練與文件管理管理者身分，本作業除第 1 項外皆以此帳號操作 |
| 管理者（單一模組） | 只具文件管理管理者身分（第 1 項） |
| 編輯者帳號 | 具文件管理編輯者角色，用於在 DM08 文件新增與編輯確認分類下拉（第 7、9、10 項） |
| 測試用分類代碼 | 一組未使用過的英文代碼，如 ZTCAT01（第 7～10 項）；測完請將該分類停用 |
| 已被使用的單位 | 文件管理單位清單中，至少一份文件或一位使用者已使用的單位（第 11 項），測完請重新啟用 |
| 參數原值紀錄 | 第 3、6 項會實際修改參數值，測試前記下原值、測完改回 |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 以只具文件管理管理者身分的帳號進入，應只看到「平台（共用）」與「文件管理（DM）」兩個分頁；兩模組管理者應看到三個分頁。 |
| 2 | 修改「登入失敗鎖定次數」後按「儲存」，應先跳出平台級確認視窗；按「取消」後，欄位應還原為修改前的值。 |
| 3 | 承上再按「儲存」並「確定儲存」，應提示「已儲存並即時生效」，清單上的參數值隨即更新。 |
| 4 | 將「帳號鎖定時間（分鐘）」設為 1441 並儲存，應被擋下並提示參數值不合法，參數值維持原值。 |
| 5 | 將「密碼到期提醒天數」設為與「密碼最長效期」相同並儲存，應被擋下並提示參數值不合法。 |
| 6 | 於文件管理分頁修改「催辦門檻天數」並儲存，不應跳出平台級確認視窗，應直接提示「已儲存並即時生效」。 |
| 7 | 於「文件分類」填入新增代碼 ZTCAT01 與新增名稱後按「新增」，該分類應出現在清單中，且於 DM08 新增文件時的分類下拉可選。 |
| 8 | 再以相同代碼 ZTCAT01 新增一次，應被擋下並提示分類碼已存在。 |
| 9 | 將 ZTCAT01 改名並按同列「儲存」，DM08 的分類下拉應顯示新名稱；該列代碼應無法修改。 |
| 10 | 對 ZTCAT01 按「停用」並「確定停用」，應標示「已停用」且 DM08 的分類下拉不再列出；按「啟用」後應恢復可選。 |
| 11 | 停用已被使用的單位，結果訊息應為「已停用，至少影響 N 份文件、M 位使用者」，N、M 為該單位的使用數。 |
| 12 | 於教育訓練職位清單將「全體」改名並儲存，應被擋下並提示為系統內建通用值；對其按「停用」並確認，亦應被擋下。 |

## DP04 通知範本維護

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者（兩模組） | 同時具教育訓練與文件管理管理者身分，本作業除第 1 項外皆以此帳號操作 |
| 管理者（單一模組） | 只具教育訓練管理者身分（第 1 項） |
| 測試者可收信之信箱 | 一個尚未註冊的 Email 信箱，用於在 DP01 使用者管理寄出帳號邀請並收信（第 2、3 項） |
| 教育訓練課程與學員 | 一門已發布、未關閉的課程，以及一位尚未加入該課程、測試者可收信的學員帳號（第 5 項）；以教師身分於 ET05 課程建立與編輯以 Email 邀請 |
| 兩個瀏覽器視窗 | 第 4 項需兩個視窗同時開啟同一範本的編輯區 |
| 範本原文紀錄 | 第 2 項會實際修改「帳號邀請」主旨，測試前記下原文、測完改回 |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 以只具教育訓練管理者身分的帳號進入，應只看到「系統信（共用）」與「教育訓練（ET）」兩個分頁；兩模組管理者應看到三個分頁。 |
| 2 | 於「帳號邀請」的主旨加註字樣後按「儲存」並「確定儲存」，應提示「範本已更新」；之後於 DP01 寄出邀請，收到的信主旨應為新內容。 |
| 3 | 承上，收到的邀請信中 {user_name}、{activate_link} 等變數應代換為受邀者姓名與實際的啟用連結。 |
| 4 | 兩個視窗同時開啟同一範本編輯，先在甲視窗儲存，再於乙視窗儲存，乙應被擋下並提示內容已被他人修改。 |
| 5 | 停用「課程邀請通知」後以 Email 邀請學員，學員應出現在該課程學員清單，但不應收到通知信；啟用後恢復寄送。 |
| 6 | 系統信（共用）分頁五種範本的「停用」應皆為灰色無法按，其「編輯」仍可開啟並儲存。 |

## DP06 排程作業總覽

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者帳號 | 具教育訓練或文件管理任一模組之管理者角色即可（本作業為兩模組共用項） |
| 已有執行紀錄之排程 | 至少一支排程已執行過數次（第 5 項要看歷程）。系統內建的每日排程通常已有紀錄，可先於清單的「最近執行」欄確認非空白 |
| 可供調整的排程 | 挑一支**調整後影響最小**的排程做第 6～9 項。這些項目會真的改變該作業的執行時間與啟停，**每項測畢請立即改回原值**；建議事先記下原本的 Cron 表達式與啟用狀態 |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 進入本作業，清單應列出各排程的 Job、說明、所屬模組、執行時點、Cron、狀態、最近執行、下次執行。 |
| 2 | 「執行時點（台灣時間）」欄應為 Cron 換算出的中文時點，例如 Cron 為 `0 8 * * *` 時顯示「每日 08:00」。 |
| 3 | Cron 為 `0 8 * * *` 之排程，「下次執行」應為某日 08:00，與「執行時點」所示時刻一致（Cron 以台灣時間解讀）。 |
| 4 | 按某列的「執行歷程」圖示，應開啟視窗列出歷次執行的起訖時間與結果；從未執行過者顯示「尚無排程執行紀錄」。 |
| 5 | 執行歷程中若有失敗或跳過的紀錄，右欄應列出其原因；同時段其他排程的紀錄應仍為成功（單一失敗不影響其他）。 |
| 6 | 按「編輯」修改 Cron 表達式並儲存，清單的「執行時點」與「下次執行」應立即依新值更新，不需重新啟動或重新登入。 |
| 7 | 於 Cron 的週幾欄填 `0` 並儲存，「執行時點」應顯示為**每週一**（週幾自週一起算，非一般慣用的週日為 0）。 |
| 8 | 於 Cron 填入不合法的表達式（例如週幾填 `7`）並儲存，應被擋下並提示 cron 表達式不合法。 |
| 9 | 將某排程的「啟用」關閉並儲存，該列狀態應變為停用且「下次執行」欄顯示「—」；重新啟用後恢復顯示。 |
| 10 | 編輯卡片的「Job ID」欄應為灰色不可輸入，僅作業名稱、說明、Cron 表達式與啟用可修改。 |
| 11 | 修改「說明」並儲存，清單該列的說明欄應更新；「執行時點」欄不受影響（兩者各自獨立）。 |
| 12 | 清單每列的操作欄應只有「執行歷程」與「編輯」兩個入口，無任何手動補跑或立即執行的按鈕。 |
