# 平台管理模組

## DP01 使用者管理

### 測試前準備

| 項目 | 說明 |
|---|---|
| 管理者帳號（主要） | 具教育訓練或文件管理任一模組之管理者角色，本作業絕大多數項目以此帳號操作 |
| 管理者帳號（另一模組） | 另一個模組的管理者帳號，用於驗證帳號為兩模組共用、所見相同（第 1 項）；兩模組管理者為同一人時此項驗不到 |
| 可收信的 Email | 一個**尚未在系統中使用過**且測試當下收得到信的 Email，用於建立帳號與完成啟用（第 5～9 項）；收不到信則整段啟用流程驗不到 |
| 已存在之帳號 | 一個已完成啟用的帳號，用於驗證 Email 重複（第 10 項）與編輯姓名（第 23、24 項） |
| 已停用之帳號 | 一個狀態為「已停用」的帳號，用於驗證啟用（第 18 項）。可先以第 16 項停用一個帳號取得 |
| 鎖定中之帳號 | 以某帳號連續輸入錯誤密碼至被鎖定（失敗次數上限為系統參數，可於 DP03 系統參數與清單維護查得），用於驗證解鎖（第 21 項） |
| 已逾期之邀請 | 一筆邀請狀態為「已逾期」者（第 15 項）。邀請效期為系統參數，建議測試前於 DP03 暫時調短效期取得，測畢再調回 |
| 跨模組驗證用環境 | 受測使用者需在教育訓練或文件管理至少有一個可操作的頁面，用於驗證停用後即時失效（第 17 項） |
| 兩個瀏覽器或兩台裝置 | 第 17 項需一邊以管理者停用、另一邊以該使用者操作，確認是否立即被拒 |
| 僅剩一名管理者之模組 | 第 20 項需停用某模組的最後一名管理者。**測畢請立即按「啟用」恢復**，否則該模組將無人可做管理作業、須由資訊人員自資料庫處理 |

### 測試項目清單

| 項次 | 測試內容 |
|---|---|
| 1 | 以教育訓練管理者與文件管理管理者分別進入本作業，兩者看到的帳號清單內容應相同。 |
| 2 | 於「關鍵字（姓名 / Email）」輸入姓名片段，清單應自動更新，不需另按查詢鈕。 |
| 3 | 於「帳號狀態」選「已停用」，清單應只列出狀態為已停用的帳號；併用關鍵字時兩項條件應同時成立。 |
| 4 | 切換至「待啟用邀請」頁籤，頁籤上的數字應等於該清單的實際筆數。 |
| 5 | 按「建立帳號」填入未使用過的 Email 與姓名，按「寄送邀請」並確認，該筆應出現在「待啟用邀請」頁籤。 |
| 6 | 承上，「帳號」頁籤**不應**出現該筆——使用者完成設定密碼前不建立帳號。 |
| 7 | 承上，收信並點連結、於效期內設定密碼後，該筆應自「待啟用邀請」消失並出現在「帳號」頁籤、狀態為啟用中。 |
| 8 | 承上，以該 Email 登入應可直接進入系統，不應再要求變更密碼。 |
| 9 | 承上，於 DP02 權限管理查看該使用者，應已具教育訓練的學員角色。 |
| 10 | 以**既有帳號**的 Email 建立帳號，應擋下並提示該 Email 已被使用，且不產生新的邀請。 |
| 11 | 以**已有待啟用邀請**的 Email 再建立一次，應擋下並提示改用重寄，且不產生第二筆邀請。 |
| 12 | 對一筆有效中的邀請按「重寄邀請」，應顯示已重寄；原連結應失效，新連結可正常設定密碼。 |
| 13 | 承上，立即再按一次「重寄邀請」，應被擋下並顯示尚需等待的分鐘數。 |
| 14 | 對一筆邀請按「取消邀請」並確認，該筆應自清單消失，且該 Email 可重新建立帳號。 |
| 15 | 邀請逾期後查看「待啟用邀請」，該筆邀請狀態應顯示「已逾期」，且其連結無法再設定密碼。 |
| 16 | 對一個啟用中的帳號按「停用」並確認，該列狀態應變為「已停用」，按鈕改為「啟用」。 |
| 17 | 承上，該使用者於教育訓練或文件管理的下一個操作應即被拒絕，不需等待其登出。 |
| 18 | 對已停用的帳號按「啟用」，狀態應恢復為「啟用中」，該使用者可再次登入。 |
| 19 | 對目前登入中的本人帳號按「停用」，應被擋下並提示無法停用自己的帳號。 |
| 20 | 停用某模組的最後一名管理者，系統應允許（不檢核至少保留一名管理者）；測畢立即按「啟用」恢復。 |
| 21 | 對鎖定中的帳號按「解鎖」，狀態應恢復為「啟用中」，該使用者可立即以正確密碼登入。 |
| 22 | 鎖定期滿後重新查詢該帳號，狀態應已自動恢復為「啟用中」，不需人工解鎖。 |
| 23 | 對某帳號按「編輯」，「帳號（Email）」欄位應為唯讀不可輸入，僅「姓名」可修改。 |
| 24 | 修改姓名後按「儲存」並確認，清單該列姓名應更新為新值，Email 不變。 |
