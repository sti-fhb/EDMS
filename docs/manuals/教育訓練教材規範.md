# 教育訓練教材撰寫規範

本規範為教育訓練簡報之**唯一判準來源**。`/sti-training` 指令只寫流程、不重述此處內容。

產出對象為**完全沒接觸過本系統**的操作人員，形式為實體授課配講師實機示範。
課程長度依模組作業數而定，由使用者於擬大綱時決定。

---

## 一、產出與位置

| 項目 | 位置 |
|---|---|
| 教材來源（md） | `docs/manuals/_training/{模組碼}-{模組名}.md` |
| 簡報產出（pptx） | `docs/manuals/教育訓練/{同名}.pptx` |
| 產生器 | `docs/manuals/tools/gen_training_deck.py` |

**md 是唯一來源，pptx 一律重新產生、⛔ 不得手改**——手改的內容下次重產即消失。版面細節（字級、留白、配色、頁尾）由產生器負責，撰寫者不處理。

```bash
python docs/manuals/tools/gen_training_deck.py <md>                # 帶完整講稿
python docs/manuals/tools/gen_training_deck.py <md> --notes brief  # 帶重點提示
python docs/manuals/tools/gen_training_deck.py <md> --notes none   # 不帶備忘稿
```

## 二、先判模組型態

動筆之前先確定該模組屬哪一型，骨架不同：

| 型態 | 判準 | 範例 |
|---|---|---|
| **A 流程型** | 有一個東西從頭被處理到尾，各作業有先後 | DM（文件：草稿 → 送審 → 發布 → 廢止）、ET（課程：建立 → 學習 → 測驗 → 核可） |
| **B 功能型** | 各作業彼此獨立，沒有共同主軸 | DP（平台管理） |

⚠️ **判準是「有沒有一個主角從頭走到尾」，不是作業多寡**。拿不準就問使用者，⛔ 不自行認定。

## 三、概述章要回答的五個問題

⛔ **不照抄他模組的張數與標題**——既有教材的投影片是這五個問題在該模組身上的答案，別的模組答案不同、張數也不同。

| # | 要回答的問題 | A 型的答法 | B 型的答法 |
|---|---|---|---|
| 1 | 這個模組管什麼、範圍到哪 | 上下游流程圖，本模組的格子標深色 | 同左 |
| 2 | 有哪些作業 | 全部作業 × 角色對照表（含編號） | 同左 |
| 3 | 我要做哪些 | 併入上表的勾選欄 | 只有一種角色時寫一句帶過 |
| 4 | **這些作業之間有沒有先後** | 有：狀態有哪幾個、狀態怎麼決定能做什麼（2 張） | **沒有：一句話帶過，不另開投影片** |
| 5 | 今天怎麼進行 | 不另開投影片，講稿帶過 | 同左 |

**第 4 題是兩型的分水嶺**。A 型要展開成兩張（有哪些階段、階段怎麼決定可執行的操作）；B 型答案是「各作業獨立」，寫一句即可。

⛔ **跨作業共用的機制不在概述章展開**（如 DM 的可見對象判定）——學員還沒看過任何畫面，講機制只會記成名詞。機制在**各作業的重點張**講，講到第三次時再用一句話收攏。

## 四、流程段的三階段骨架

每個流程段（A 型的主流程、各條岔路；B 型的各功能群）一律照這個順序，**先看流程、再看畫面、最後才講細節**：

```
1. 流程圖      這一段有哪些作業、怎麼接起來
2. 實際操作    講師實機示範
3. 重點        不講就會做錯的事
```

**理由**：陷阱型的提醒（「某欄是確認者唯一看得到異常的地方」）在沒看過畫面之前聽不懂；放到示範之後講，學員有畫面可以對應。

**示範的切法**：按「處理對象走到哪裡」切，⛔ **不按角色切**——跨角色的作業（如 DM 的文件由編輯者送審、審核者於 DM02 簽核中心核准）會被切在中間。單次示範超過 **8 分鐘**時，於中間安排一個停頓讓學員發問。

**實際操作那張怎麼寫**：投影片上只列**兩三條操作順序**（如「新增文件並送審 → 簽核中心核准 → 文件庫查得到」），⛔ 不列逐步操作；逐步內容（登哪個帳號、點哪個鈕、要展示什麼）全部寫進 `> 提示：`，那是給講師自己看的。事前要備妥的測試資料也寫在提示。

## 五、流程圖的畫法

| 元素 | 規則 |
|---|---|
| 方塊主標 | **作業編號 ＋ 側欄上顯示的名稱**（不是手冊名稱） |
| 方塊副標 | 這一格在做什麼，或負責角色；⚠️ **同一張圖的副標要同一種**，不可一半寫動作一半寫角色 |
| 無編號者 | 狀態（如「送審中」）、他模組的動作、非作業的前提，一律不給編號 |
| 深色強調 | 本模組範圍用 `**節點**` 標記；未標記時首尾自動深色 |
| 箭頭標籤 | 標該步驟的**動作**（送審、核准），非狀態 |

**一條線一個 flow 區塊**。不相連的兩條線（如 DM 的退回線與廢止線）各畫一行，⛔ 不要串成一條——學員會以為一定要先走完前一條。

⚠️ **高度限制**：帶副標的流程圖一張約佔 4.6 公分，版面可用高度 12.9 公分。因此**兩個帶副標的流程圖，底下最多再放一條要點**；要放兩條就得拆成兩張投影片，或把要點併成一條。

## 六、重點張的取捨

**判準只有一條：不講的話，使用者會不會做錯或卡住？**

| 寫上投影片 | 移到講稿 | 移到提示（問起再講） |
|---|---|---|
| 不可逆的動作 | 不知道只是覺得奇怪的 | 罕見分支 |
| 會影響別人的 | 畫面上看得到的 | 設計緣由 |
| 系統會擋下來的條件 | 系統會強制的（不填送不出去） | 他模組的細節 |
| 兩段式、要按確認才算數 | 操作方式（同一件事有兩種做法時的選擇） | |

**格式**：每條前面標作業名（`**送審**：…`），**依流程順序排**。一張 4～6 條，超過就拆或砍。

## 七、總結章要回答的兩個問題

⛔ **不照抄他模組的張數**——下表是要回答什麼，不是要有哪幾張。

| 要回答的問題 | A 型的答法 | B 型的答法 |
|---|---|---|
| 今天學了什麼 | 流程圖再走一次，方塊副標改標**負責角色**；⛔ 不重複講規則 | 各功能群收攏成一張 |
| 之後遇到問題怎麼辦 | 學員最容易卡住的幾題（症狀 → 原因），末條指向操作手冊與其〈常見訊息與處置〉章 | 同左 |

課程以結語頁收尾（標記 `> 結語頁`）。

課堂上不展開、但學員會反覆回去查的對照表，放在結語頁之後並標記 `> 隱藏投影片`——放映時跳過、列印與 PDF 仍在。**沒有這類資料就不放**。

## 八、內容原則

- ⛔ **不放系統截圖**：畫面會改版、截圖很快過期；實際畫面由實機示範補足。流程示意圖不在此限。
- ⛔ **過細的操作陷阱不寫**：學員尚未熟悉基本操作，講了更亂；寫入提示，問起再補。
- **側欄名稱與手冊名稱不同時 MUST 標出來**（如 ET02 手冊叫「學員」、側欄叫「學員學習表現」），否則學員照教材去側欄找不到。
- **作業編號與手冊檔名一致**，學員課後查得到那一本。
- 作業清單、側欄名稱一律**查 `frontend/src/layouts/navItems.ts` 與 `docs/manuals/{模組}/` 實際檔名**，⛔ 不憑記憶。

## 九、md 語法

### 檔首

```markdown
# {模組名}（{模組碼}）｜教育訓練
> 英文名：Document Management
> 課程日期：
> 講師：
> 封面：（封面頁講稿）
> 大綱：（大綱頁講稿）
```

英文名、課程日期、講師為封面欄位，留空則該列不印。其餘封面資訊（案號、系統、主辦單位）取自 `manual_config.py`；⚠️ 其中案號與主辦單位目前為「（待確認）」，產簡報前須補正式值（見 `/sti-training` 步驟 7）。

⚠️ **講師欄必填，填該模組負責人**。判法比照操作手冊之作者——**取該模組操作手冊的 git 主要提交者**，對照 `manual_config.AUTHORS` 的帳號表換成正式姓名：

```bash
git log --format='%an' -- docs/manuals/{模組碼}/ | sort | uniq -c | sort -rn
```

⛔ 不沿用他模組的講師、⛔ 不自行推斷；查無對應帳號或提交者有多人難以判定時問使用者。課程日期未定時留空即可。

### 結構

| 語法 | 產出 |
|---|---|
| `## 章名｜English` | 章節分隔頁；英文為該章各投影片共用的小標 |
| `### 標題` | 一張投影片 |

### 版型

| 圍籬 | 用途 |
|---|---|
| ` ```flow ` | 橫向流程圖。`節點｜副標`、`**節點**` 深色、`-標籤->` 箭頭標籤 |
| ` ```cards ` | 並列卡片（2～4 張），標題＋說明文字；說明以「；」分行 |
| ` ```cards-block ` | 同上，但各項畫成深色方塊、三項以上自動分兩欄；項目內「：」分主副標 |
| ` ```steps ` | 編號步驟，直向排列 |
| 表格 | 二維對照用；儲存格以「；」分行，短欄自動置中 |
| `- 條列` | 一張 4～6 條 |

### 標記

| 語法 | 作用 |
|---|---|
| `> 講稿：` | 完整備忘稿，可續行（下一行以 `>` 開頭即接續） |
| `> 提示：` | 重點提示版備忘稿，給講師自己看 |
| `> 重點：` | 版面上的重點框 |
| `> 隱藏投影片` | 放映時跳過，列印與 PDF 仍在（附件用） |
| `> 結語頁` | 沿用封面版式（大字、無頁碼），用於「謝謝聆聽」 |

**強調**：`**粗體**` 會轉成強調色，一張不超過兩處；表格內不轉色。
