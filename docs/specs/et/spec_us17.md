# User Story 17 — UCET017 核可查詢（ET04）

> 對應 UC：UCET017 ｜ 功能選項：ET04（核可查詢）｜ Priority：P2 ｜ Wireframe：[核可查詢](../../wireframes/et/index.html) ｜ 返回總檔：[spec.md](spec.md)
> 2026-07-17 新增（客戶需求：線下核可查詢）。核可資料由 [spec_us16.md](spec_us16.md) US16 寫入。

提供**核可紀錄查詢**，依角色分兩種視角：

- **教師 / 管理者視角**：於「核可查詢」畫面**依學員姓名**查詢核可課程，結果含課程名稱、核可結果（通過 / 不通過）、核可時間、核可人，以及是否已撤銷與撤銷原因。管理者不限課程；**教師依核可結果分流**（2026-09-21 SA 裁示 C，見 `FR-ET-US17-02`）。
- **學員視角**：學員登入後僅能查看**自己「已通過核可」**的課程清單（不顯示不通過 / 撤銷紀錄、不得查他人）。

本 US **不提供**核可證明 / 結業證書輸出（2026-07-17 客戶確認）。查詢屬唯讀，不含任何核可 / 撤銷動作（動作於 [spec_us16.md](spec_us16.md) US16）。

**Priority**: P2

**Why this priority**: 為客戶明確提出之「用姓名查學員通過課程」需求，與 US16 核可作業成對交付；屬查詢類唯讀作業。

**Independent Test**: 管理者於核可查詢輸入學員姓名可查得該學員之全部核可課程（含通過 / 不通過 / 撤銷）；教師查同一姓名時僅見全部課程之通過紀錄，他人課程之不通過 / 撤銷 / 考核備註不出現；學員登入僅能查得自己「已通過」之課程，查不到不通過 / 撤銷紀錄、亦查不到他人；查無資料時顯示對應空狀態。

**Acceptance Scenarios**:

### 教師 / 管理者視角

1. **Given** 教師 / 管理者進入核可查詢畫面，**When** 輸入學員姓名（可模糊）查詢，**Then** 系統列出符合學員之核可課程：課程名稱、核可結果（通過 / 不通過）、核可時間、核可人
2. **Given** 某學員某課程之核可已被撤銷，**When** 教師 / 管理者查詢，**Then** 該筆顯示「已撤銷」狀態與撤銷原因、撤銷人 / 時間
3. **Given** 管理者查詢，**When** 檢視結果，**Then** 可查得**全部課程**之全部學員核可紀錄（不限自己建立之課程）
4. **Given** 教師（非管理者）查詢，**When** 檢視結果，**Then** 可查得**全部課程**之「通過且未撤銷」紀錄；**不通過、已撤銷與考核備註**僅顯示自己 owner 之課程（2026-09-21 SA 裁示 C）
4a. **Given** 教師查詢結果中含他人 owner 課程之通過紀錄，**When** 檢視該列，**Then** 其考核備註為空（`FR-ET-US17-01a`）
4b. **Given** 教師（非管理者）進入本畫面，**When** 檢視，**Then** 常駐顯示其可見範圍之說明
5. **Given** 查詢條件查無核可紀錄，**When** 系統回應，**Then** 顯示空狀態提示

### 學員視角

6. **Given** 學員登入後進入「我的核可 / 已通過課程」，**When** 系統載入，**Then** 僅顯示該學員**自己「已通過」（有效未撤銷）**之課程清單（課程名稱、核可時間）
7. **Given** 學員有「不通過」或「已撤銷」之核可紀錄，**When** 學員檢視，**Then** 該些紀錄**不顯示**（學員端僅見已通過）
8. **Given** 學員嘗試查詢他人之核可紀錄（竄改參數 / 直呼 API），**When** 系統處理，**Then** **拒絕**並不回傳他人資料
9. **Given** 學員目前尚無已通過核可之課程，**When** 進入畫面，**Then** 顯示空狀態提示

### 不提供證書

10. **Given** 任一角色檢視核可查詢結果，**When** 檢視畫面，**Then** **不提供**核可證明 / 結業證書之下載 / 列印功能

## Functional Requirements

- **FR-ET-US17-01**（2026-09-30 由 #464 改訂）: 系統 MUST 提供核可查詢畫面（ET04）供教師 / 管理者依學員姓名（可模糊比對）查詢**受訓完成狀況**，結果 MUST 含課程名稱、結果（通過 / 不通過）、**通過時間**、核可人，撤銷者 MUST 標示「已撤銷」並顯示撤銷原因 / 撤銷人 / 時間。

  「**通過**」有兩種成立方式，畫面上 MUST NOT 區分：

  | 課程 | 通過的條件 | 通過時間 | 核可人 |
  |---|---|---|---|
  | `REQUIRE_APPROVAL = true` | `ET_APPROVAL.RESULT = PASS` 且 `IS_REVOKED = false` | `APPROVED_AT` | 執行核可者 |
  | `REQUIRE_APPROVAL = false` | 該課程全部未刪除項目皆已完成（`enrollment/rules.is_course_completed`）| `ET_ENROLLMENT.COMPLETED_AT` | 無（顯示「—」）|

    > **原條文**：「查詢**核可紀錄**，結果含…**核可時間**」。
    >
    > **改訂理由**：2026-09-30 手測回報「核可查詢沒有呈現不需要核可的課程但已經完成 100% 的學員」。`REQUIRE_APPROVAL = false` 之課程永遠不會產生 `ET_APPROVAL` 列（核可端點直接 409），而本畫面原本只查該表——但本節 Clarifications 所載之客戶需求是「**排班需知某人受訓是否完整**」，那是完課，不是線下核可。
    >
    > ⚠️ **需核可課程中「已完課但尚未核可」者 MUST NOT 列出**（#464 Q2 裁示 A）——需核可課程之完成定義包含線下核可。此為**已知的假陰性**：查詢者看到「查無」可能讀成「未受訓」，而該學員實已完成線上部分、僅待教師核可。
    >
    > ⚠️ **`REQUIRE_APPROVAL` 於發布後仍可變更**。同一 (課程, 學員) 兼有核可紀錄與完課時，MUST **以核可紀錄為準**——教師之明確判斷（含不通過與撤銷）不得因事後變更該設定而被自動規則覆蓋。
    >
    > ⚠️ `COMPLETED_AT` 於 #464 起寫入（第一次完課當下、只寫一次、回退不清除）。**活化前即已完課之既有資料該欄為空**，畫面顯示「—」並排序於最後（`NULLS LAST`）；正式機由 migration 從頭建立，不受影響。
- **FR-ET-US17-02**: 管理者 MUST 可查得全部課程之全部學員核可紀錄。教師（非管理者）之可查範圍 MUST 依**核可結果**分流（2026-09-21 SA 裁示 C，取代原「於 plan 階段最終確認」之待決措辭）。**不需核可課程之完課 MUST 視同「通過且未撤銷」——全部課程可見**（2026-09-30 #464 Q1 裁示 A；完課不具負面對應面，與通過同側）：

  | 紀錄 | 教師可見範圍 |
  |---|---|
  | `RESULT = PASS` 且 `IS_REVOKED = false` | **全部課程** |
  | `RESULT = FAIL` | 僅自己 owner 之課程 |
  | `IS_REVOKED = true`（不論原 `RESULT`）| 僅自己 owner 之課程 |

  🔴 **撤銷後的通過歸在受限側**：被撤銷之通過其 `RESULT` 仍為 `PASS`，僅依 `RESULT` 分流會使其撤銷原因（承載誤植 / 考核有問題等負面判斷）對全體教師可見。

  ⚠️ 本分流之**必要配套**：教師視角 MUST 常駐說明其可見範圍。缺此說明時，教師無從分辨某門課程未出現於結果係「尚未考核」或「考核未通過且非其所開設」，較「僅可查自己課程」更易誤導。
- **FR-ET-US17-01a**: 核可備註（`ET_APPROVAL.RESULT_NOTE`）MUST 僅對該課程 owner 與管理者顯示，其餘一律回傳空值（2026-09-21 SA 追加裁示）。

  **為何另立一條**：`FR-ET-US17-02` 的分流切的是**結果**維度，而 `ApproveReq.result_note` 允許 `PASS` 亦附備註——負面評語掛於通過紀錄上時，會隨「通過可查全部」流向全體教師。裁示 C 之理由（考核評價不應供同儕教師任意翻閱）於欄位維度同樣成立。

  ⚠️ MUST 由後端遮蔽（回傳空值），MUST NOT 僅由前端不渲染。

- **FR-ET-US17-03**（2026-09-30 由 #464 改訂）: 學員視角 MUST 僅顯示該登入學員本人**已通過**之課程清單（「通過」之定義同 `FR-ET-US17-01`，**含不需核可課程之完課**），MUST NOT 顯示不通過 / 已撤銷之紀錄，MUST NOT 顯示他人之任何核可資料
    > **原條文**：「僅顯示…**已通過（有效未撤銷）**之課程清單」——即僅含核可紀錄。
    >
    > **改訂理由**（#464 Q4 裁示 A）：不納入的話，學員完成一門不需核可的課，自己的清單裡看不到那門課；且同一畫面對教師是「受訓完成狀況」、對學員是「核可紀錄」，兩者定義不一致。
- **FR-ET-US17-04**: 系統 MUST 於後端以登入者身分控管查詢範圍，對學員存取教師 / 管理者查詢或查詢他人資料之請求 MUST 拒絕（不以前端隱藏為唯一防線）
- **FR-ET-US17-05**: 本 US MUST NOT 提供核可證明 / 結業證書之產生 / 下載 / 列印功能
- **FR-ET-US17-06**: 查無符合條件之核可紀錄時系統 MUST 顯示對應空狀態提示
- **FR-ET-US17-07**（2026-09-29 由 #439 改訂）: 教師 / 管理者查詢時，**關鍵字（姓名或 Email）與課程 MUST 至少提供一項**；兩者皆未提供者 MUST 拒絕（關鍵字去除前後空白後為空視同未填）。關鍵字未給時 MUST 以所選課程查詢該課程之核可紀錄；課程未選時 MUST 維持跨課程之關鍵字查詢（行為與改訂前一致）。
    > **原條文**（2026-09-21 SA 裁示 A）：「學員姓名 MUST 為必填」。理由兩半——「留白查詢等同取得具受訓紀錄者之可列舉名冊」與「不給條件即列全部無對應需求」。
    >
    > **改訂理由**：第二半已不成立——2026-09-29 手測回報「**必須先知道姓名才查得到，但使用者常常正是不知道有誰可以查**」，本條所預留的「日後如需班級核可總表由 ET02 承接」並未發生，而 ET02 是以課程管理學員、不是查核可紀錄。
    >
    > **第一半（名冊可列舉）在課程路徑上未被放寬**，由兩道條件一起承接，**缺一即等同取消**：
    >
    > 1. 兩者皆未給仍拒絕（`ET_APPROVAL_006`）——那才是原本的「留白查全部」
    > 2. **非管理者僅得以自己開設之課程篩選**（見 FR-ET-US17-08）
    >
    > 🔴 **但關鍵字路徑本身並不構成防列舉控制，本條未改變這件事，且該路徑目前有一個已知缺口。**
    > `DP_USER.EMAIL` 為 `NOT NULL` 且關鍵字採 `contains` 比對，故單一請求 `keyword = "@"`
    > 即對全體使用者命中，可於可見範圍內整批取回具受訓紀錄者之清單（含 `USER_ID` 與姓名對照）。
    > 該缺口由 #436（關鍵字加入 Email 比對）引入，**非本次改訂造成**，追蹤於 **#456**。
    >
    > ⚠️ 真正在收斂列舉的是另外兩件事（與 `approval/router.py` 模組 docstring 一致）：
    > **母體限制**（只回有 `ET_APPROVAL` 列的人，非全員名冊）與**角色受控**（`ET_TEACHER`
    > 由管理者指派、非自助取得）。⛔ 請勿把「關鍵字必填 / 至少給一個」讀成防列舉的防線。
    >
    > ⚠️ 本條之放寬**未動到 FR-ET-US17-02 的可見範圍分流**（裁示 C）：教師依然僅得見他人課程之「通過且未撤銷」。改變的是「如何找到紀錄」，不是「誰看得到哪些紀錄」。

- **FR-ET-US17-08**（2026-09-29 新增，#439）: 以課程篩選時，非管理者 MUST 僅得指定**自己所擁有（`OWNER_ID`）之課程**，其餘一律拒絕；查無該課程者亦 MUST 拒絕（fail-closed）。管理者不受此限。課程選項清單 MUST 僅含**已存在核可紀錄**之課程，且對非管理者 MUST 僅列其自有課程。
    > **為何需要本條**：FR-ET-US17-07 使「不給關鍵字」成為合法查詢，而課程選單僅是前端呈現。少了本條，教師得以指定他人課程一次取得**該課程全部通過者之名單**而無須知悉任何姓名——即 FR-ET-US17-07 原條文所防之名冊可列舉，改以課程為單位重演。
    >
    > **課程選項以核可紀錄為母體**（而非課程清單）的理由：核可紀錄多數落於**已結束**之課程，而 ET01 課程清單之 `scope=all` 恰排除該類課程（`FR-ET-US7-01`）；沿用將使管理者遍尋不著最相關之課程且無任何提示。

    ⚠️ 選項清單為空時 MUST 說明成因（載入失敗 / 尚無核可紀錄），MUST NOT 呈現可開啟但無內容之選單。

## 相關 Clarifications 摘錄

- 教師 / 管理者可查**全部學員**；學員只能查**自己已通過**的課程（2026-07-17 客戶確認）
- **教師的可查範圍於 2026-09-21 收斂為裁示 C**（見 `FR-ET-US17-02`）：客戶原始需求「用姓名查學員**通過**課程」天生跨課程（排班需知某人受訓是否完整），但「不通過」與其考核備註屬該課程之考核評價，不應供同儕教師任意翻閱。管理者不受此限，故客戶需求仍可由管理者路徑完整滿足
- **不需**核可證明 / 結業證書（2026-07-17 客戶確認）
- 學員端僅見「已通過」，不見不通過 / 撤銷紀錄（隱私與體驗考量）
- 核可資料來源為 ET_APPROVAL（[spec_us16.md](spec_us16.md) US16 寫入）；查詢唯讀
